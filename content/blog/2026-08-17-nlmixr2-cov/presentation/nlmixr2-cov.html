nlmixr2 7.0: the covariance step, all grown up

Matthew Fidler

On behalf of the nlmixr2 team

This talk, in three pictures

Three things changed in the covariance step for this release:

  1. The default covariance step now covers every parameter.

  2. Two new covariance methods, S-A and I-M-P that can be used almost anywhere.

  3. A genuine new covariance method that Hidde created – an exact analytic covariance

1. A full covariance step

Let’s start with the new full covariance

Residual-error parameters used to come back with no standard error

Now the additive residual error standard deviation is calculated for all methods – before 7.0 the standard error was missing.

That was a deliberate choice, not an oversight

  • We, as a nlmixr2 team, think that when you simulate with uncertainty, the omega and sigma terms should be simulated from the inverse Wishart distribution, not from standard errors
  • Getting real omega and residual standard errors also required meaningfully more implementation effort than the approach we originally took

7.0 adds the full covariance step on top of that – it is not a reversal of how we think about simulating uncertainty.

We’ve always leaned toward using the inverse Wishart distribution for simulating uncertainty in omega and sigma; when implementing nlmixr, we thought by not having these standard errors, others would simulate with uncertainty with the inverse Wishart distribution too.

Additionally, getting real standard errors for those terms took real additional work.

This new work really doesn’t change how we think about simulating with uncertainty.

However, these values inform how well these parameters are estimated and are frequently requested (and useful in other methods).

Fit the model, and add.sd comes back with a real number

fit <- nlmixr2(pheno, pheno_sd, est="focei")
print(fit)

add.sd – SE about 0.008, roughly 0.9% RSE – a number that, before this release, simply was not there.

fit$cov

The full covariance ($cov) also carries the Omega block, named by random effect – om.eta.cl, cov.eta.cl.eta.v – so you can find what you’re looking for without guessing at row order.

If you look at the full covariance matrix, you’ll also see the omega block standard errors.

The covariance matrix is named so you will never guessing at which covariance term belongs to which estimated omega element.

Only three things still don’t get a standard error

  • Everything else – structural, covariate, and residual-error thetas
  • fix()ed parameters – there is nothing to estimate a standard error for
  • inter-occasion variability (IOV) parameters – those are individual-level, not population-level
  • mixture-probability parameters on the mlogit scale – yes, we have mixtures now too, more on that another day

So what’s still skipped? Fixed parameters, Inter occasion variability parameters and mixture probability parameters. Everything else is in the covariance matrix by default.

2. sa and imp break free of one estimation method

The second change is bigger than it sounds: two covariance methods stopped being tied to one specific estimation method.

sa and imp used to be locked to one estimation method each

The new S-A and I-M-P covariance methods can be requested for practically any fit and also be computed post fit.

This post-fit covariance step occurs at the converged estimates of the mixed effects model.

setCov() switches a finished fit without refitting anything

fit <- nlmixr2(pheno, pheno_sd, est="focei")

# the SAEM Louis stochastic-approximation FIM, on a focei fit,
# without refitting anything
setCov(fit, "sa")

# the importance-sampling Monte Carlo observed information, same fit
setCov(fit, "imp")

setCov() calculates the covariance and installs it on the fit. Once calculated, it is saved, so switching back and forth costs nothing extra.

setCov calculates the new covariance and folds it right into the fit. Once it’s calculated, it’s cached, so you can flip between covariance methods on the same fit without paying the calculation cost twice.

covMethod is now a shared vocabulary of nine tokens

token what it is
"r,s" sandwich, solve(R) %*% S %*% solve(R) – the focei-family default
"r" / "s" just the Hessian half or the cross-product half of the sandwich
"analytic" exact observed-information covariance, matches NONMEM’s $COV MATRIX=R
"sa" SAEM Louis stochastic-approximation FIM (Kuhn & Lavielle 2005)
"imp" importance-sampling Monte Carlo observed information
"vi" variational covariance – emvi/fbvi only
"nlme" nlme’s own standard errors – nlme only
"linFim" / "fim" SAEM’s linearized / accumulated Fisher information – saem only
"" skip the covariance step

Here’s the full list of supported covariance matrix methods. Some are still only found in their corresponding methods. If you specify an empty string, the covariance step is simply skipped.

Most families’ defaults now reflect what they’re actually best at

family default covMethod note
focei / foce / laplace / agq "r,s" unchanged
saem "sa" falls back "analytic" then "linFim" when out of scope
imp / impmap / qrpem "imp" impCov=TRUE argument is gone – this is just the default now
nlme "nlme" unchanged, but "analytic" is now selectable too
npag / npb "imp" currently does not have its own method
emvi / fbvi "vi" now honors an explicit override instead of overwriting it

This lists the default covariance methods. Most defaults stayed put, because they were already the right choice for that family.

3. The analytic covariance: an exact standard error

The last piece is covMethod="analytic" itself, and this one is based on Hidde’s work.

The exact gradient stops one derivative short of a standard error

For the new analytic method the population objective is a data term plus a log determinant penalty term.

The gradient only needs second order sensitivities. For more details, you can read the corresponding paper.

A finite-differenced Hessian has a harder accuracy floor than a gradient

  • A finite-differenced gradient’s achievable accuracy scales with the inner-problem tolerance to the two-thirds power
  • A finite-differenced Hessian’s achievable accuracy is worse – it only scales to the one-half power
  • … and it needs a step size tuned by hand: too large and you get truncation bias, too small and round-off makes it erratic – sometimes not even positive definite

The analytic form carries no step size – it is limited only by the accuracy of the sensitivity and ODE solutions underneath it.

The analytic gradient has no step size and no finite difference noise, so it is not erratic or biased – it is exact. It is only limited by the accuracy of the ODE systems themselves.

On warfarin data, the analytic value matches NONMEM – with no step to tune

Warfarin PK, one-compartment oral absorption, 10 subjects, correlated clearance/volume random-effect block, diagonal absorption-rate random effect – the analytic standard error matches an independent NONMEM run to every figure shown.

On a warfarin case study – one compartment, oral absorption, ten subjects, a correlated random effect block on clearance and volume, and a diagonal random effect on the absorption rate – the analytic standard error matched an independent NONMEM run to every figure they reported. The finite difference standard error only tracked that value over a narrow middle band of step sizes – too large a step and it’s biased, too small and it gets erratic. The analytic value just sits there, flat, no step size involved at all.

Why this matters

  • The default covariance step now covers every estimated theta, residual-error parameters included
  • sa, imp, analytic and the finite-difference methods now travel across mixed-effects fits, switchable after the fact with setCov()
  • covMethod="analytic" gives you an exact standard error with no finite-difference step size to tune
  • Spot-check an "r,s" covariance against "analytic" or "sa" without paying for a second fit
  • The covariance step you gave up on for npag/npb is worth trying again – it’s there now
  • Tell us where the analytic covariance falls outside its scope

To summarize: the default covariance step now covers:

  • every estimated parameter, S-A, I-M-P, analytic and the finite-difference methods.

  • you can switch after the fact with set cov

  • the analytic covariance gives you an exact standard error.
