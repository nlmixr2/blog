IOV: prior(iov.cl)?

parameters {
  real<lower=0> iov_cl;               // estimated magnitude, on the sd scale
  matrix[N, 1] z_rx_iov_cl_1;         // occasion 1
  matrix[N, 1] z_rx_iov_cl_2;         // occasion 2
}
transformed parameters {
  matrix[1,1] L_rx_iov_cl_1 = [[1]];  // unit variance, FIXED
  eta[, 4:4] = z_rx_iov_cl_1 * L_rx_iov_cl_1';
}
model {
  to_vector(z_rx_iov_cl_1) ~ std_normal();
  iov_cl ~ cauchy(0, 1);              // <-- the declared prior(iov.cl)
}

Is the per-occasion structure the one you would write by hand; prior(iov.cl) describes the sd (the iovXform scale), not the variance – right convention?; and with no prior declared the magnitude is left flat and improper (warned, not substituted) while omega diagonals get a default half-Cauchy – should it get one too?

Each occasion gets its own eta with a fixed unit variance and those are scaled by an estimated magnitude theta, here called I-O-V underscore C-L.

Three things I would still like checked. First, is the per occasion structure what you would have written by hand?

Second, the magnitude is on the standard deviation scale by default, is that the convention you would expect?

And third, if you declare no prior at all, the magnitude is now left flat and improper. It does warn you.

In contrast, the omega diagonals get a default in that situation.

Should an I-O-V magnitude get a default too, and if so, which one?

Mixtures: is the eta prior on the right side of the log_sum_exp?

matrix[2*N, 1] eta;                    // component-major: 1..N, then N+1..2N
...
to_vector(z_eta_cl) ~ std_normal();    // BOTH components, OUTSIDE the mixture
...
for (i in 1:N)
  sumLL += log_sum_exp(log(p1)    + llCond[i],
                       log1p(-p1) + llCond[N + i]);

The claim is that the component-specific etas’ priors factor out of the marginalization, so only the conditionals go inside. Is that the marginal you want – both components’ etas carry a prior whether or not the subject is in that component? Also: p1 is passed into theta even though the conditional is asserted to be p-free, and the per-subject logLikSubj used for LOO is the marginalized value.

Two eta styles: do these target the same posterior?

etaParam = "noncentered" (default)

matrix[N, 1] z_eta_cl;

eta[, 2:2] = z_eta_cl * L_eta_cl';

to_vector(z_eta_cl) ~ std_normal();

etaParam = "centered"

matrix[N, 1] etaP_eta_cl;

eta[, 2:2] = etaP_eta_cl;

for (i in 1:N)
  etaP_eta_cl[i] ~
    multi_normal_cholesky(rep_vector(0, 1), L_eta_cl);

Both hand the same eta matrix to the external conditional, so neither needs a Jacobian on our side – Stan owns the whole eta prior either way. Is that reasoning right, and would you expect the two to agree to within MCSE on a real hierarchical PK posterior (as opposed to just in principle)?
