nlmixr2scm is on CRAN!

Happily, nlmixr2scm, which does stepwise covariate modeling (SCM) for nlmixr2 models, is now on CRAN. It took a while - seems they’re very busy now that everyone is churning out packages with AI - but it’s finally there.

install.packages("nlmixr2scm")

If you’ve built covariate models in NONMEM, you’ve probably used scm in Perl-speaks-NONMEM. nlmixr2scm follows the same approach (Jonsson & Karlsson, 1998), and it works directly on an nlmixr2 fit. You don’t need to write control streams or config files or any of that kind of thing, although the command will probably be quite lengthy…

How SCM works

SCM searches in two phases, and both use likelihood-ratio tests (you probably know this, but a bit of underlining is always useful):

  1. Forward inclusion. Starting from the base model, it tests every candidate parameter-covariate relationship. The one that gives the largest significant drop in OFV is added, and the search repeats until no remaining candidate passes the forward threshold (p < 0.05 by default).
  2. Backward elimination. Starting from the final forward model, it removes each included relationship one at a time. Any relationship whose removal does not raise the OFV enough to pass a stricter threshold (p < 0.01 by default) is dropped.

runSCM() writes the covariate terms into the model body for you. Continuous covariates are centered (at the median, or at a reference value you choose), and categorical covariates are expanded into indicator columns. It takes the original, untransformed data.

A quick example

We’ll start from a one-compartment warfarin PK model:

library(nlmixr2)
library(nlmixr2scm)

pkdata <- nlmixr2data::warfarin[nlmixr2data::warfarin$dvid == "cp", ]

warf_pk <- function() {
  ini({
    tka <- log(1.15)
    tcl <- log(0.135)
    tv  <- log(7.0)
    eta.ka ~ 0.40
    eta.cl ~ 0.25
    eta.v  ~ 0.10
    prop.err <- 0.10
  })
  model({
    ka <- exp(tka + eta.ka)
    cl <- exp(tcl + eta.cl)
    v  <- exp(tv + eta.v)
    linCmt() ~ prop(prop.err)
  })
}

fit_base <- nlmixr2(warf_pk, pkdata, est = "focei",
                    control = foceiControl(print = 0))
## calculating covariance matrix
## [====|====|====|====|====|====|====|====|====|====] 0:00:00

Let’s test body weight (as a power or linear relationship) and sex on clearance and volume…

scm <- runSCM(
  fit        = fit_base,
  data       = pkdata,             # needed: the base model doesn't use wt or sex
  varsVec    = c("cl", "v"),       # parameters to test
  covarsVec  = "wt",               # continuous covariates
  catvarsVec = "sex",              # categorical covariates
  shapes     = c("power", "lin"),
  pVal       = list(fwd = 0.05, bck = 0.01),
  saveModels = FALSE,              # quick exploratory run: nothing written to disk
  print      = 0,
  confirm    = FALSE
)

If you want to control exactly which relationships are tested, pass pairsVec instead of the full varsVec × covarsVec grid. You can also use includedRelations to force known relationships (allometric weight on clearance, for example) into the backward-elimination model.

Real-world searches

Real-world SCM runs often fit hundreds of candidate models, and nlmixr2scm has several features for that:

  • Caching and resume. With saveModels = TRUE (the default), every candidate fit and step table is saved to outputDir. If a run is interrupted, call runSCM() again with the same outputDir and it picks up where it stopped. restart = TRUE starts from scratch instead.

  • Parallel fitting. workers fits the candidates within each step in parallel through future. rxThreads sets how many rxode2 threads each worker uses. runSCM() checks workers * rxThreads against your physical core count before it starts, so that it doesn’t quietly murder your computer by maxing out its capacity.

    runSCM(fit_base, data = pkdata, varsVec = c("cl", "v"), covarsVec = "wt",
       workers = 4, rxThreads = 1)

  • Protection against bad fits. Some candidate fits stall at the zero-effect initial estimate. This happens sometimes with ODE models. runSCM() detects these stalled candidates and refits them from a starting value obtained with a quick 1-D profile. Candidates that land on an implausible OFV are retried from perturbed initial estimates, and the best attempt is kept. Both behaviours are switched on by default. By default, a p-value that underflows to zero also counts as implausible, which means very strong effects (an OFV drop of more than about 70 for one parameter) get retried too. If you trust those, retryOnUnderflow = FALSE saves the extra fits.

  • Fixed centering. centers = c(wt = 70) centers weight at 70 kg instead of the per-dataset median. The coefficients then keep the same reference across datasets.
