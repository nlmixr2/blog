If you are at ACoP 2026 (October 11-14, National Harbor, Maryland), come find the nlmixr2save poster. This post covers the same material, with code you can run.

nlmixr2save is on CRAN and version 0.2.0 is out now:

install.packages("nlmixr2save")

Two problems

Problem 1: Fits you can’t open later. Nonlinear mixed-effects models can take minutes to weeks to fit. Once one is done, you want to keep it. The usual way is saveRDS(), but that ties the result to R’s binary format and to how nlmixr2 stored the fit internally.

That second tie actually broke. nlmixr2 used the qs package to compress fits. When qs was removed from CRAN, nlmixr2est moved to qs2, which broke backward compatibility for saved fits. It later moved to base R serialization, and old qs2 fits can still be read only if qs2 is installed. A fit that depends on how a particular package version stored its internals is not really an archive.

Problem 2: Running the same model again for no reason. During development you source a script, or render a Quarto/R Markdown report, over and over. Each time, every nlmixr2() call runs again, even when nothing about the model, data, or settings changed.

nlmixr2save fixes both.

A model to work with

one.cmt <- function() {
  ini({
    tka <- 0.45; label("Log Ka")
    tcl <- log(c(0, 2.7, 100)); label("Log Cl")
    tv <- 3.45; label("log V")
    eta.ka ~ 0.6
    eta.cl ~ 0.3
    eta.v ~ 0.1
    add.sd <- 0.7
  })
  model({
    ka <- exp(tka + eta.ka)
    cl <- exp(tcl + eta.cl)
    v <- exp(tv + eta.v)
    linCmt() ~ add(add.sd)
  })
}

Saving a fit as text

saveFit() breaks a fit into its parts and writes each one as text. Models, including the final estimated model, become nlmixr2/rxode2 R source. Tables (estimates, objective function values, the fit table, the data) become CSV. Everything is bundled into one .zip:

fit <- nlmixr2(one.cmt, theo_sd, est = "focei",
               control = list(print = 0))

Unzip it and you can read nearly all of the fit in a text editor, a spreadsheet, or another language (a couple of small components, such as the session info, are still .rds). No R is needed to see what was estimated. In R, loadFit() rebuilds the fit:

A loaded fit is a working fit, not a snapshot. Diagnostic plots, VPCs, and model piping all work, so you can use it as the starting point for the next model:

plot(fit2)
vpcPlot(fit2)
fit3 <- fit2 |> model(ka <- exp(tka)) |> nlmixr2(est = "focei")

The saved fit also records the nlmixr2est and rxode2 versions that produced it. If you load it later with different versions installed, you get a warning explaining why a rerun might not match exactly.

Caching with :=

The second tool is the one you will use daily. Change <- to :=:

fit <- nlmixr2(one.cmt, theo_sd, est = "saem")   # always runs
fit := nlmixr2(one.cmt, theo_sd, est = "saem")   # runs once, then loads

That is the only change. Here is how := works:

  1. It computes a hash of the model, the data, and every estimation option. For random calls, such as simulations, it also records the random seed at the start.
  2. If a cache file with that hash (and, for random calls, the same starting seed) exists, := loads it. For random calls, it also restores the ending seed state, so the rest of your script sees the same random numbers it would have seen if the call had run.
  3. Otherwise the call runs and the result is saved.

The first call fits the model:

system.time(
  fitS := nlmixr2(one.cmt, theo_sd, est = "saem",
                  control = list(print = 0))
)
#> [====|====|====|====|====|====|====|====|====|====
#> ====|====|====|====|====|====|====|====|====|====] 0:00:00
#> [====|====|====|====|====|====|====|====|====|====] 0:00:00
#> [====|====|====|====|====|====|====|====|====|====] 0:00:00
#> [====|====|====|====|====|====|====|====|====|====] 0:00:00
#>    user  system elapsed 
#>  19.219   2.921   7.834

The same call again loads from disk:

system.time(
  fitS := nlmixr2(one.cmt, theo_sd, est = "saem",
                  control = list(print = 0))
)
#>    user  system elapsed 
#>   0.315   0.000   0.315

Change anything that matters and it runs again. Here, the number of burn-in iterations changes:

system.time(
  fitS := nlmixr2(one.cmt, theo_sd, est = "saem",
                  control = list(print = 0, nBurn = 250))
)
#> [====|====|====|====|====|====|====|====|====|====] 0:00:00
#> [====|====|====|====|====|====|====|====|====|====] 0:00:00
#> [====|====|====|====|====|====|====|====|====|====] 0:00:00
#> [====|====|====|====|====|====|====|====|====|====] 0:00:00
#>    user  system elapsed 
#>  18.049   2.632   6.446

Hashing the data is smarter than hashing the whole data frame. The hash only uses the columns that affect estimation: standard columns, model covariates, and table$keep columns. If you add a notes column to the data, fitS still loads from the cache. If you change DV, it refits.

Beyond nlmixr2()

:= works with any function. For fits, the cache is the text .zip above. For everything else, it is an .rds file that stores the result and the hash:

set.seed(42)
sim := rxSolve(fit, nStud = 10)

The first time the script runs, this simulates and saves sim.rds with the starting seed. The next time the script is sourced, it starts from the same set.seed(42), so := loads sim.rds and moves the seed to where the simulation left it. If the starting seed is different, for example a second call later in the same session, := simulates again.

To make your own stochastic function seed-aware, register it with saveFitRandom("mySimulate").

Two notes:

  • := has to see the long-running call directly. suppressMessages(nlmixr2(...)) always runs, because the inner call runs before := can check the cache.
  • The cache file is named after the variable on the left, so fitS becomes fitS.zip.

Options for reports and projects

Version 0.2.0 adds options for cached work that lives in a project or a rendered document:

option default what it does
nlmixr2save.dir "." directory for cache files
nlmixr2save.prefix "" prefix for cache file names, e.g. one per report
nlmixr2save.check TRUE set to FALSE to trust any existing cache and only run when the file is missing
nlmixr2save.data TRUE set to FALSE to leave the original data out of saved fits
nlmixr2save.checkVersion TRUE warn (or ask, when interactive) if a cache came from different package versions

nlmixr2save.check = FALSE is useful when the cache is committed to version control. The document renders the same way on every machine, even with different nlmixr2 versions installed. When you do want to rerun everything, nlmixr2saveInvalidate() deletes every file in nlmixr2save.dir whose name starts with nlmixr2save.prefix. Give the cache its own directory or prefix first; with the defaults, that means every file in the working directory.

Sharing a fit without the data

Often you can share a model but not the subject-level data behind it. nlmixr2saveShare() takes an existing saved fit and writes a smaller copy next to it. The original is not changed:

nlmixr2saveShare("fit")                # fit-noData.zip
nlmixr2saveShare("fit", noFit = TRUE)  # fit-noData-noFit.zip

The first copy removes the data and keeps the predictions and residuals. The second copy also removes the per-observation table, leaving the model, estimates, objective function, eta table, and parameter history. Anything that needs the data won’t work on the copy, including VPCs and refitting. The sharing vignette lists exactly what is lost.

Summary

  • saveFit() / loadFit(): fits stored as R source and CSV that stay readable and don’t depend on a binary format.
  • fit := nlmixr2(...): rerun only when something changed, with reproducible random seeds.

If you source scripts over and over or render reports with fits in them, try switching <- to :=.
