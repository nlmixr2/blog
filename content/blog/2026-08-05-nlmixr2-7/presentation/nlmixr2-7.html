nlmixr2 7.0: focei solves in parallel

Matthew Fidler

On behalf of the nlmixr2 team

This release, in five pictures

This release covers five main updates:

  1. Solving in parallel.
  2. fast exact population gradients
  3. Changes to the defaults.
  4. A more robust SAEM.
  5. Additional experimental engines and ODE solvers.

1. Solving in parallel

First, Bill, Hidde, and I worked on parallelizing the estimation.

In nlmixr2 6 every subject waited its turn; now they solve together

In the old releases every subject waited its turn. Now, they all solve and optimize together for the conditional estimation methods and most of our other estimation algorithms. This means if you have a multi-core computer, your solving speed will be significantly faster.

2. Exact gradients, and the fast variants

Next, Hidde and I introduced an exact gradient in the fast variants.

The old outer gradient paid for one extra solve per parameter, per subject

Previously, calculating the outer gradient – the part of the optimization problem focused on getting the best population values and residual parameters – required taking your base model and optimizing every individual to get the best individual estimates. Then, you had to perform finite differences for each population parameter and redo the full optimization for every subject. This resulted in p plus one, times n total optimizations.

Our new analytic method allows you to skip those redundant optimizations to get the population gradients. Based on the Almquist 2015 sensitivity equations, this exact gradient means you are no longer fighting optimization and solver noise.

The gradient you have decides the optimizer you want

The gradient dictates the optimizer you want to use. The standard method still uses finite differences for the population values, which results in a noisy gradient. Because of this, the default has changed to a derivative-free method called BOBYQA. Since a gradient is never calculated, no finite differences are ever used with it. However, individual optimizations still use exact gradients with n1qn1.

Our fast method uses these exact sensitivity equations and gradients, so we rely on a Quasi-Newton optimization type – specifically, L-BFGS-B3c.

foceif starts each individual search from where the last step says the eta went

Because the fast method starts its individual search by projecting where the individual estimate should be for the next optimization, it takes fewer steps to find the right individual estimate at a new theta.

Once the eta moves, the old curvature is the wrong curvature to hand n1qn1

This efficiency made us rethink what data we need to save between steps. Previously, we saved the old curvature and sent it to the n1qn1 optimizer. However, if that curvature was wrong for the new theta, it would take longer to zig-zag to the minimum. Now, by recalculating the curvature we find the gradient and the minimum much faster.

3. New defaults for standard focei

Because of these updates, we have new defaults in the standard method.

Standard focei still differences its gradient, so it now optimizes with bobyqa

Our standard method now optimizes using a quadratic curve through spread-out samples. This naturally follows the minimization trend instead of getting stuck in the noise. This is especially useful for hard or complex surfaces.

The old optimizer is one control argument away

The pre-7.0 outer optimizer:

fit <- nlmixr2(one.cmt, theo_sd, est="focei",
               foceiControl(outerOpt="nlminb"))

As close to 6.x as 7.0 gets – and it will not be bit-for-bit:

fit <- nlmixr2(one.cmt, theo_sd, est="focei",
               foceiControl(outerOpt="nlminb",
                            warm="save",
                            sigdig=4,
                            resetThetaP=0.05,
                            resetThetaFinalP=0.15))

If you prefer the old behavior, nlminb is still available.

Four defaults moved, which is why focei will not reproduce a 6.x fit

You can see from this slide an overview of the changes we made.

  1. the default population optimizer was changed

  2. the curvature, or Hessian, was calculated before every optimization

  3. resetting of thetas to the centered value when etas drift is turned off

  4. we changed the default to sigdig=3 to better match many open-source tools.

4. Making saem more robust

We also made SAEM significantly more robust.

saem estimates a no-eta parameter directly instead of sampling it

In the previous release, population parameters with no random effect on them were continuously sampled until the variance shrank at the end. While this usually settled, it could become biased if it didn’t settle exactly where it needed to. If we use a bounded regression – it honors the exact location and drops the error measured by RMSE by 16-fold.

A separated random stream is what makes restarting the SA phase possible

We also changed how random number streams function. By using thread-safe random streams, every single point in the optimization can be reproduced while remaining completely independent. This allows you to safely extend the chain rather than throwing away previous fits.

5. Many new ODE solvers, and new engines

Finally, we’ve added more experimental ODE solvers and Nonlinear mixed effect estimation methods

AutoSwitch reaches for the stiff solver only when the problem turns stiff

You can now combine stiff and non-stiff solvers – similar to lsoda – using methods like DOP853 and Rosenbrock4. Rosenbrock4 is new, and there are many new ODE solving methods available in our packages.

The new engines are research code and may change without a deprecation cycle

We’ve also introduced new experimental optimization methods like IMP, VAE and new conditional-estimation variants.

Where this lands

  • focei solves in parallel on every OpenMP-enabled platform
  • foceif gets an exact population gradient from one augmented solve
  • The defaults moved, deliberately, based on speed and accuracy of optimization. Unfortunately this means 6.x numbers will not come back in this release.
  • saem is more accurate on parameters without a random effect
  • The covariance step you gave up on is worth trying again (especially with analytic)
  • Tell us where the experimental engines break

To summarize: parallel solving works on every OpenMP-enabled platform, the fast methods utilizes an exact population gradient, our classic method defaults have moved to a derivative-free optimizer for better accuracy on noisy parameters, SAEM is more robust, and we have many new experimental ODE and estimation routines.
